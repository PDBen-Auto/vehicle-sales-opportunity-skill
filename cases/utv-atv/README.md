## 案例由什么组成

1. 问题：北美UTV、ATV具体型号的销量/注册/在用量，可以从哪些渠道取得？
2. 渠道：比较PPM、MIC/S&P、SSI、Lightspeed、Moto Canada和OEM资料，明确口径、细度与访问条件。
3. 公开研究：完整车型保有量不可得时，整理官方历史批次，**只做已知批次在假设下的情景**。
4. 数据：系列/明确合并组、国家、来源、批次、年款或销售窗口、去重、参数、未知与缺口。
5. 产品：Excel与自包含页面，同一dataset驱动，桌面表格、手机卡片、筛选与调参。
6. 核验：快照hash、批次边界、公式、HTML/CSV/Excel一致性、界面与导出。
7. 研究：从可追溯条目设计需求/适配/竞争/经济验证，不把情景数当份额或真实需求。

## 当前快照与没有完成的部分

本包固定首个已完成版本：2026-11-17，124个目录条目、105个来源，US63/CA15/MX1个条目有可计算批次，完整车型保有量全部unknown。源文件与其完成manifest逐文件核对后复制，原数据与数字未脱敏、未换成合成值。

**ATV完成的是渠道调查；数据页面是UTV研究，排除了ATV和配件。** 原对话新的年款/版本细化、图片修复和精度提升正在进行，不属于本次已完成快照。目录可列出版本不等于数量可拆分到版本。不能把这一案例称为“完整北美UTV/ATV销量数据库”。

原始输出中的检查、归档状态和日期是历史记录。本仓库包装、复现与发布另有记录，不改写旧检查冒充新执行。

从仓库根目录运行：

```sh
python cases/utv-atv/reproduce.py --workdir out/utv-case
```

这会检查原完成快照、复制到新工作目录、**离线**重建dataset和HTML、核对关键结果。原124条目录、各国计数及全车型unknown都必须保留。`--workdir`已存在则停止；不会自动联网或写回案例快照。

如现有环境具备Pillow和openpyxl，可在复现目录执行：

```sh
python out/utv-case/过程/validate_scenarios.py
```

原3053项检查、37项浏览器检查和Excel敏感性记录随案例保留，是原完成版本证据；仓库CI只代表其实际执行的快照、算术、离线重建和通用生成器测试。

## 更新时怎么做

`过程/collect_sources.py`和`collect_catalogs.py`保存原公开查询逻辑，仅在明确要求更新时运行，**它们会联网并更新工作缓存**。不要在仓库快照内直接执行；先用复现目录隔离。`collect_sources.py`在原探索阶段另有Polaris API补录，本包以冻结merged缓存为准，重新查询的结果不保证与历史快照相同。厂商目录403/超时不代表车型不存在，错误需记录。

`collect_images.py`保留原图处理流程和已知失败；URL空格编码、403和缺图是后续修订事项，不伪造已修复。图片用于历史批次识别，不代表现款、适配或安全状态。第三方图片/商标的原权利不因放入本案例而授予公开商用权；本包不更改其许可。

首次版情景参数仅为研究假设，不是实证存活率、统计置信区间或严格下限。用于业务决策前仍需需求、适配及经济验证。
