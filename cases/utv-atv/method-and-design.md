# 真实案例的方法与页面设计

## 1. 先区分能够回答的问题

“每款一年卖多少”对应零售流量；“上牌多少”对应注册；“现有多少仍在用”对应存量。公开召回只对应某些历史车辆，不能直接回答上述完整市场问题。原调查先找商业车型级渠道，再在公开证据可用范围内做探索性批次情景。

## 2. 建立可追溯对象

`国家 → 稳定车型系列/明确合并组 → 批次/年款或销售窗口 → 原始公告 → 假设情景`。

目录与数量分开：124条目录不是完整车型数量，目录身份不代表各国在售。104个命名系列/子车型与20个合并组可共存用于解释，但不能把父组和子项相加。子项无可拆分数量时明确unknown。

关键表：`model_catalog.csv`（对象）、`cohort_components.csv`（批次与范围）、`source_ledger.csv`（URL、日期、本地快照、hash）、`cohort_scenarios.csv`（情景）、`known_gaps.csv`（缺口）。标准销量/VIO表保留空表头，避免下游误当已获得观察值。

## 3. 原始证据到批次数量

- 公开API按关键词产生候选，以RecallID去重；原候选池不是已经审计完全部历史。
- 人工核对具体车型、产品类别、车辆台数、国家、年款/VIN/销售窗口，排除ATV与配件。
- 官方目录补充型号身份；403/超时如实保留，不把访问失败当不存在。
- 每个保留来源保存原始快照和SHA-256，计算表保留来源关联。

## 4. 重复、合并与异常

| 案例 | 正确处理 |
|---|---|
| Honda Talon 34000已包含32000 | 不加成66000 |
| Pioneer 1000的82000与早期65000/56000 | 保留选定批次，不叠加重叠公告 |
| Rhino 450/660的120000与700的25000 | 明确不同子集可合为145000，但不再拆量 |
| RANGER XD1500车辆10500与绞盘1336 | 只用车辆，不能混计配件 |
| Brawley两公告210与190 | 保留差异，首版选较新较小190，不相加 |
| 合并Can-Am或MULE组 | 保留合并边界，不编造各版本数量 |
| 年款与销售日期冲突 | 保留原文与window_basis；不修造日期 |

## 5. 可复算的压力情景

`情景批次数 = 历史公告车辆数 × 兑现系数 × 年保留系数 ^ 压力车龄`。

`压力车龄 = max(0,2026-min(窗口起年,最早起售年))`。更严80%/88%，基准90%/93%，较缓95%/97%。这些是研究者设定，不是经验标定。以最老年计龄；更严/基准向下取整，较缓向上取整：1000以上按100、100以上按10，其余按1。

例：RZR XP1000/XP4历史两个不重叠窗口共128000台，基准52600。未覆盖年款/VIN、未召回车辆、真实存活/迁出/停用和未售库存均未完整核对；因此不是全车型存量，也不保证是严格下限。区间不是统计置信区间。

## 6. 页面产品设计

- **总览**：国家、研究日期、批次可计算条目数、完整保有量未知等前提先可见。
- **桌面表格**：品牌/用途/范围筛选、分页，历史批次数、基准和压力区间分列。
- **手机卡片**：主要数字直接出现在卡片，避免重要值全部落到横表右侧；保留查看依据。
- **系列详情**：统计范围、年款/销售窗口、原始数量、来源、重复说明、公式与缺口。
- **参数面板**：调整研究假设，页面即时重算，CSV导出当前国家/筛选/参数；Excel为独立副本，不假称双向同步。
- **历史图片**：官方公告图用于识别当时召回批次，不代表现款/适配。52张可解码图，其他条目缺图或失败，保留原因；合并组继承图片时不得误认精准版本。
- **交付**：数据和图片内嵌HTML，不依赖外部脚本/CDN；Excel、说明、数据与来源快照保持相对路径。

`过程/dashboard.template.html`是完整模板，`build_report.py`将同一dataset与图片manifest嵌入页面；`build_workbook.mjs`读取同一dataset生成公式工作簿。

## 7. 研究入口与验收

本例最适合追问“哪些具体范围已有可追溯批次”“哪个年款/版本还缺数量”“什么材料能验证使用场景”。不能直接按情景值排名推出市场份额或配件需求。适配、真实需求、价格/成本、渠道与竞品需另有材料。

检查层次分开：原始快照hash → 唯一键/关联 → 年款/VIN重叠 → 批次算术/舍入 → HTML/CSV/Excel一致性 → 图片解码 → 桌面/手机交互 → 业务有效性。前七项通过不意味着最后一项成立。

原完成版本有3053项数据/交付检查、37项浏览器检查；完整原检查脚本与结果随包保留。本次移植使用独立离线复算和界面回归，记录在新的验证说明。原生Microsoft Excel重算尚未实测，不把Artifact Tool敏感性测试替代它。

## 下一版应做的事

1. 年款、版本目录与数量归属分别细化；合并批次继续保留，禁止平均分摊。
2. 修正空格URL编码等可复现图像错误；403/缺证据继续unknown。
3. 用真实同口径历史零售/注册/VIO替换薄弱输入，取得许可后再处理；不把更多召回简单累加当更精准。
4. 保留来源、参数和结果版本，对历史回填、边界变更和实际新增分开出差异。
