# 从销量信号到可审阅研究

本包描述如何分析已有材料与设计研究，不列销量数据来源或采集方案。没有额外材料时，只交付研究计划与证据缺口。

## 第一层：只说数字证明的事实

为每项记录：市场/车系边界、期间、两期销量、绝对变化、同比、缺失和样本位置。先排除时间窗、车系重命名、聚合变化、回填或缺数造成的假异常。

基础脚本将每个序列分为：

- `scale_growth`：当期规模、正增量与增幅都过阈值，值得排入优先调研。
- `small_base_growth`：增幅过阈值，但规模或增量有限，先核对基数。
- `decline_review`：下降幅度和绝对减少都过阈值，研究供给/生命周期/竞争等不同解释。
- `zero_base`：基期为零，无法计算同比；不能直接等同新上市。
- `insufficient_data`：窗口不完整，先解决可比性。
- `watch`：未触发上述条件，保留观察，不静默丢弃。

这些是透明入口规则，不是商业吸引力或风险分数。

## 第二层：建立至少一个可被推翻的假设

| 信号 | 合理研究问题 | 不能直接下的结论 |
|---|---|---|
| 大盘子+稳定增量 | 哪个用户场景频繁且现有方案不理想？ | 车卖得多所以任意配件都会卖得好 |
| 同级竞品相反增减 | 产品、价格、供应、组合还是统计边界不同？ | A增长全来自抢走B用户 |
| 新代际与销量拐点同时发生 | 改款实际何时交付？接口/尺寸/用户场景改变了吗？ | 所有历史销量都属于新代际，旧配件必然适配 |
| 持续下降但历史规模大 | 是退市尾量、短期缺货还是需求变化？是否有可服务的使用场景？ | 新车销量少所以存量服务不存在，或累计销量就是在用车量 |
| 小基数高增长 | 绝对量够不够支持小批量验证？ | 增速高就意味着高收入/高利润 |

## 第三层：按用途设计验证

汽配/附件方向依次核对：具体车系/代际/配置与接口 → 使用场景与痛点证据 → 当前替代方案和竞品缺点 → 可实施样件/安装测试 → 渠道需求证据 → 成本/退换/履约约束。需要用户持有或另外授权的材料才可开展的环节标清，不自动访问账号或系统。

车型市场研究方向：定义比较集合 → 核对可比窗口 → 对照已有产品变化、供给和价格记录 → 保留竞争解释 → 明确什么证据能区分这些解释。没有控制变量、对照或其他可信识别设计，不宣称销量因果归因成立。

## 评审记录格式

```text
ID / 市场 / 车系与代际范围 / 时间窗
数据观察：数值、变化与覆盖边界
假设：谁，在什么场景，遇到什么可解决问题
支持材料：用户已有材料标识、日期、适用范围、支持的具体主张
反驳与替代解释：至少一个有可能成立的解释
未验证项：需求、适配、竞争、渠道、成本分别列出
最小验证：样本选择、动作、验收量、期限、成本上限（未知则待定）
停止条件：关键适配失败/需求证据不足/成本不可行/权限未具备等
业务状态：当前任务可试用 / 特定条件下适用 / 暂不接入
执行成熟度：仅候选 / 已完成材料评审 / 已做验证；写实质证据
```

没有真实反馈和适配/经济材料时，状态通常为“特定条件下适用：先验证”，而非宣布值得投资。不要编造用户访谈、订单、转化率、复购或 ROI。

## 合成案例

Aster Canyon：虚构美国SUV，2024年1–6月12000辆，2025同期15600辆，增加3600辆、30%。

可形成“为该代际车型研究可拆卸储物附件”的候选，但销量只能提供研究优先级线索。仍需确认具体代际的储物尺寸、用户痛点、现有方案、安装干涉和单位经济；没有材料时这些全部为待验证。销售累计值不用于推算在用车量或可服务总市场。
