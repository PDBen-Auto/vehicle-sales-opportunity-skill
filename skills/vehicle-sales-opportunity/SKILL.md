# 车辆销量可视化与机会调研

把用户已经持有、允许处理的销量数据，变成能核对数字、比较车型并启动调研的交付。北美示例按美国、加拿大、墨西哥分开展示，方法可用于其他市场。

线上呈现示例：[北美车型数据看板](https://north-america-vehicle-dashboard.pages.dev/)。这是原项目的在线示例，不是本包的合成演示；访问条件以页面当时状态为准。运行本 Skill 不依赖该站，也不复制站内内容。

## Implementation Basis and Dependencies

实现依据：稳定车系主键、同口径月度汇总、同期配对比较、交互式 SVG/HTML 和“观察—假设—验证”研究方法。脚本是独立重写的离线工具，包内示例全部为虚构车型与合成数字。

| 依赖 | 必需性与提供方 | 用途与核验 | 不可用时 |
|---|---|---|---|
| 用户已有销量表及口径说明 | 必需，用户提供 | 确认市场、日历期间、单位、车系边界、缺失定义和处理权限 | 缺关键口径先列缺口，不能推断或补数 |
| Python 3.10+，仅标准库 | 使用附带脚本时必需，由宿主提供 | `python --version`；执行 `scripts/build_dashboard.py --help` | 可改用宿主表格/可视化工具，保留相同规则并注明未运行脚本 |
| 文件读写权限 | 必需，由用户授权目录提供 | 只读输入，写入新的输出目录 | 权限失败报告具体路径，保留旧版本 |
| Codex 或可阅读 Agent Skills 的助手 | 执行完整研究流程时必需 | 能读本文件和按需引用的 references | Python 工具仍可独立生成数字与研究候选，但不自动完成业务评估 |
| 浏览器 | 可视化验收时必需，宿主提供 | 直接打开本地 HTML；检查桌面/手机和交互 | 先交付文件，视觉验收标未完成 |
| 表格工具 / XLSX 读取库 | 仅原始输入为 Excel 时需要 | 检查实际工具；将已有表规范化为约定 JSON | 请用户提供已有表的 CSV/JSON 导出，不安装未知依赖 |
| 产品、用户、适配、成本等已有材料 | 机会验证时按问题需要，用户提供 | 记录材料日期、适用范围及支持/反驳的主张 | 仅形成待验证假设，不宣布需求、适配或 ROI 成立 |

核心执行不需要账号、密钥、网络、付费 API 或 MCP。发布网页、上传文件、访问外部业务系统需本轮另有相应授权；本 Skill 的运行命令只写本地结果。

## Inputs

| 名称 | 必需性、格式及用途 | 校验、缺失与边界 |
|---|---|---|
| `dataset` | 必需；用户已有 JSON，详见 [数据合同](references/data-contract.md)。月度记录包含市场、稳定车系 ID、分类、年月、销量及状态 | 仅处理获准内容；拒绝重复键、负数、未来已报告值、错误单位、未声明字段。真实表先在本地适配；不能直接公开 |
| `comparison` | 必需；当前/基期完整日历月份，例 `2025-01..06` 对 `2024-01..06` | 同月份且相隔一年；不拿全年对 YTD；脚本不支持自动拆季度或年度值 |
| `thresholds` | 可选；最小规模、最小绝对变化、增减幅，默认 10000 辆、1000 辆、10% | 只决定候选研究入口，不是投资评分；不同频率/业务目标应显式调整 |
| `research_brief` | 业务评估时需要；Markdown/JSON，例“评估 SUV 后备厢配件，预算/渠道待定” | 没有则生成通用待办；不擅自设定真实预算、用户需求或商业承诺 |
| `supporting_materials` | 可选；用户已有的产品、代际、用户反馈、竞争、适配或经营材料 | 只读必要内容；日期/市场/对象不明则不用于因果解释；不在公开包中嵌入私有材料 |
| `output_dir` | 必需；本地尚不存在的主题版本目录 | 禁止覆盖既有交付；不要把私有数据输出到公开仓库 |

## Outputs

全部写入 `output_dir`，不联网、不上传、不改写输入。脚本写入前完整验证输入；失败返回非零；输出目录已存在则拒绝覆盖。

| 文件 | 含义、内容与验收 | 部分/失败行为 |
|---|---|---|
| `dashboard.html` | 自包含交互 HTML；国家/分类/搜索/排序、规模与增速矩阵、配对样本分类对比、明细及月度下钻、筛选 CSV 导出；断网也可打开 | 缺数显示“未知”，无可比序列显示空状态；导出仅含当前筛选行 |
| `analysis.json` | schemaVersion 1；逐车系月度记录、窗口覆盖、可比性、绝对变化、同比、分类汇总、输入 SHA-256 | 不可比项保留且标原因；分母为零时同比为 null |
| `opportunities.json` | schemaVersion 1；每个序列的信号类型、事实、假设、验证问题、下一步和停止条件；状态 `candidate_only` | 这是调研队列，不是已完成的业务评审 |
| `report.md` | 数字摘要、市场分开统计、样本边界和研究待办；便于复核 | 无数据/无基期如实写缺口 |
| `qa.json` | 输入指纹、记录数、不可比车系、排除原因和运行状态 | `pass` 仅表示结构和内部算术通过，不证明数据真实性、覆盖完整或业务结论 |
| `research-review.md` | **助手另行完成**；按 [机会研究](references/opportunity-research.md) 逐项判断，区分事实/解释/缺口/验证 | 未有足够证据可写“待验证”，不能把候选脚本输出称为完成调研 |

## Workflow

1. 明确本轮问题：做销量月报、比较车型、还是筛选某类配件/服务的调研入口。确认当前窗口、市场、单位、输出目录和处理权限。
2. 阅读 [数据合同](references/data-contract.md)。按稳定车系整理已有数据；保持车型与聚合系列边界。缺数不改零、销量不改保有量、日历年 CY 不改车型年 MY。只有年度/季度数据时，按其原粒度制作对应视图；**不能喂给月度脚本或平分成月份**。
3. 规范化后执行脚本。脚本校验失败先修正适配或报告缺口，不改数字“凑平”。月度数据示例（命令中的路径以技能目录为基准）：

   ```sh
   python scripts/build_dashboard.py --input assets/demo.json --output /path/to/new-output
   ```

4. 按 [呈现方法](references/visualization.md) 检查总览、矩阵、排名、增减、月度下钻和筛选联动。示例脚本提供轻量基础；需要图片、代际带、复杂交叉比较或 Excel 时，基于获准材料扩展，不冒称基础脚本已实现。
5. 原始行与关键指标交叉核对：至少检查一个增长、一个下降、一个零基期和一个缺失序列；说明配对样本覆盖。分类比较仅汇总两期都完整的同一组车系；不把样本占比称市场份额。
6. 阅读 [机会研究](references/opportunity-research.md)。从规模、变化绝对量、变化率、生命周期和业务约束生成研究问题。竞争迁移、产品换代、价格或供给变化只能是解释候选，不能由销量直接断言。
7. 用已有获准材料做逐项评审，写 `research-review.md`。真实适配、需求、渠道、成本不明就给最小验证行动和停止条件。未完成外部研究时写清“只完成数据观察和研究设计”。本包不提供数据来源和采集方案。
8. 直接打开 HTML，核验桌面与窄屏、键盘访问、图表标题/单位/空值、筛选、详情和导出；清理临时浏览页。交付看板、数字 JSON、研究评审和 QA，说明哪些仍待验证。

## Example

请求：“这里是美加墨月度销量，做分类可视化，并找 SUV 配件调研入口。”

先比较各国同年 1–6 月与上一年 1–6 月。虚构 Aster Canyon 从 12000 到 15600 辆，可描述“+3600 辆、+30%”；**不能据此说某配件需求增长 30%**。将“该车型车主是否存在储物痛点、代际接口是否变化、现有竞品是否已覆盖”列为验证题；没有证据时结论保持待验证。

## Definition of done

- 市场、窗口、单位和车系口径可见；缺失、零基期、聚合边界和排除项保留。
- 主要数字可回溯到用户输入行及指纹；不包含数据来源清单或采集方法。
- 所有承诺的文件存在；筛选、图表、详情和导出已经实际检查。
- 机会评审将销量信号与需求/适配/盈利验证分开，不用热度替代商业证据。
- 发布或共享前仅带获准内容；合成案例标明 synthetic，默认不携带真实输入。
